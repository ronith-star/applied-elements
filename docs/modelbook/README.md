# Technical Model Book

`modelbook.pdf` (202 pages) is the reference document for every model module in
`src/ae`. `modelbook.tex` is its source. Neither is written by hand: both are
generated by `build.py` from the docstrings in `src/ae`, so the prose in a
module chapter IS that module's prose and cannot drift from it.

## Rebuilding

```
PYTHONPATH=src python docs/modelbook/build.py          # measures the test suite
PYTHONPATH=src python docs/modelbook/build.py --reuse-tally   # reuses the cached tally
cd docs/modelbook && pdflatex modelbook.tex            # run three times for the ToC
```

Three `pdflatex` passes are needed: one to typeset, one to resolve the table of
contents, one to settle page numbers after the ToC changes the pagination.

`--reuse-tally` exists because a full suite run takes roughly twenty minutes,
which is too slow to repeat on every typesetting iteration. The cache records
the commit it was measured at, the time, and a provenance note, and the book
prints all three; a cache measured at a different commit is discarded and
re-measured, and a cache with no provenance note aborts the build rather than
letting the book imply a measurement it cannot describe.

## What each file does

| File | Role |
| --- | --- |
| `build.py` | Reads docstrings from the AST, executes every doctest and supplementary example, reads the validation record, harvests the symbol table, emits LaTeX. |
| `rst2tex.py` | Converts the RST subset the docstrings actually use into LaTeX. Not a general RST implementation: it handles the constructs present in this package and aborts on anything else rather than mangling it. |
| `examples.py` | 19 supplementary worked examples. 10 modules in `src/ae` carry no doctest at all (`agent/decisions`, `core/registry`, `core/site`, `econ/uncertainty`, `econ/unit_economics`, `ml/surrogate`, `physics/chlorination`, `physics/diffusion`, `physics/leaching`, `physics/reagents`), so an example was required for those; the remaining 9 targets have doctests as well, and the example exercises a composed calculation across an object graph that a single-expression doctest does not reach. Every fixture is synthetic and tagged ASSUMED. |
| `_suite_tally.json` | Cached suite measurement, with its commit and provenance. |
| `build_report.json` | What the last build measured, including every discrepancy it found. |

## Guards that stop a defect reaching a reader

Each of these was added after the defect it names was found in a built page,
and each aborts the build rather than degrading the output:

1. An unhandled RST construct aborts, rather than being passed through as text.
2. A misaligned RST simple table aborts. A cell wider than its `=` rule was
   silently truncated, which put the fragment ``:math:`\textbackslash{}mathcal{R``
   in the symbol table.
3. A symbol used with two different units emits both rows and a recorded
   conflict, rather than keeping whichever unit was seen first.
4. A worked example that raises aborts. A worked example that cannot run is
   worse than none, because the reader cannot tell.
5. A named LIMITATIONS section that has been renamed aborts, rather than
   silently emptying the chapter that quotes it.
6. A suite-tally cache with no provenance note aborts.
7. A README with no synchronisable `modelbook.pdf` page count aborts. The count
   here read 194 while the shipped PDF was 202, because the number was typed
   once and the book rebuilt twice after; it is now read from the compiled PDF
   on every build.
8. A DOI check file that does not cover every distinct DOI in the current
   validation record makes the book name the shortfall rather than generalise
   the checks it does have. The findings chapter asserted that each distinct
   DOI had been verified against CrossRef when 8 of 17 had been, so that
   sentence is now generated from `_doi_checks.json` and states exactly the
   coverage the recorded results support.

Guards 1 through 6 abort the build. Guards 7 and 8 differ: 7 aborts only when
the README cannot be synchronised at all (a stale number is corrected rather
than fatal), and 8 never aborts, because a missing check is a weaker claim to
state, not a reason to withhold the chapter.

## Known limitations of the book itself

1. The book covers 27 modules, which is every non-empty module in `src/ae` at
   the commit recorded on its title page. It does not cover `scripts/`.
2. Worked-example outputs are the values produced on the build machine. Several
   print floating-point results whose last digits are platform-dependent in
   principle, so exact reproduction on another machine is not guaranteed.
3. The prose is the modules' own. Where a module hedges, the book hedges
   identically; the book does not add analysis the modules do not contain.
